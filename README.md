# E2E Living Docs

## このリポジトリで試していること

**エージェントが実行しやすいE2Eテストを作り、そのE2Eで確認した操作を根拠に、マニュアルサイトを自動で更新できるか。** これをTaskFlowという小さなWebアプリで検証する、ローカル中心のPoCです。

想定している流れは次のとおりです。

```text
人がシナリオと期待結果を定義
  → エージェントが画面を操作
  → コードが実際の画面状態を判定
  → 成功した結果とスクリーンショットを検証
  → 操作マニュアルと品質レポートを生成
  → ドキュメントサイトをビルド・検証
```

大切にしているのは、エージェントの「できました」という返答を合格とみなさないことです。**画面の状態を明示的に確認でき、必要な証跡がそろった場合だけ、マニュアルを更新する**ことを目指しています。

## 現在できること・まだできていないこと

| 領域                   | できること                                                                                                                                                        | 現状・未確認のこと                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| エージェント向けE2E    | 自然言語で操作を指示し、操作後は決定的な画面アサーションで判定するテストを6シナリオ定義しています。各テストは保存状態を初期化し、画面画像を記録する構成です。     | OpenAIサインインを使った6件すべての実E2E成功runは未確認です。テストコードがあることや単体テスト成功は、エージェントが実ブラウザーを正しく操作できた証明ではありません。                                                           |
| シナリオと手順の連携   | `packages/scenarios/`に操作目標・手順・期待結果・画像ラベルを置き、docgenがこれを使ってマニュアル候補を作る構成です。                                             | E2Eテストの`agent.act(...)`とアサーションは`packages/e2e-tests/tests/`にも個別に記述されています。現時点では、両方が1つの実行可能な定義から自動生成されるわけではありません。内容がずれないかを今後確認・改善する必要があります。 |
| 証跡とドキュメント生成 | docgenはE2Eレポートを検証し、シナリオ別のMDX、品質レポート、画像を候補出力します。全シナリオの成功、明示的な成功アサーション、条件を満たすPNG証跡などが必要です。 | 正常・失敗・skip・assertion欠落・不正パスなどのオフライン契約テストはありますが、実E2Eレポートからの生成はまだ通していません。                                                                                                    |
| 一括更新               | `pnpm docs:sync`でE2EからBlumeのビルド・リンク検証までを順に行い、全工程の成功後にローカル生成物を更新する実装です。                                              | `docs:sync`全体の成功runは未確認です。コマンドはE2Eを起動するため、認証が使えない状態では実行できません。現在のマニュアル・品質ページは未検証であることを表示しています。                                                         |
| 自動運用・公開         | 成功した一括実行から、ローカルのドキュメントを更新する設計です。                                                                                                  | GitHubへのpushを起点にした実行、定期実行、GitHub Actions、オンライン公開・自動デプロイはありません。更新には開発者がローカルで`pnpm docs:sync`を実行する必要があります。                                                          |
| 対象アプリ             | TaskFlowの追加・編集・完了・削除・再読み込み後の保存・空入力検証を扱います。                                                                                      | これはTaskFlowだけのPoCです。任意のWebアプリへそのまま適用できる汎用基盤ではありません。                                                                                                                                          |

### E2Eが確認する6つの操作

| ID       | エージェントが行う操作 | コードが確認する結果                   |
| -------- | ---------------------- | -------------------------------------- |
| `TC-001` | 「牛乳を買う」を追加   | 一覧にタスクが表示される               |
| `TC-002` | タスク名を変更         | 変更後の名前が表示される               |
| `TC-003` | チェックボックスを選択 | 完了状態に切り替わる                   |
| `TC-004` | 指定タスクを削除       | 一覧から対象が消える                   |
| `TC-005` | ページを再読み込み     | 保存したタスクが残っている             |
| `TC-006` | 空白だけで追加を試す   | 入力エラーが表示され、タスクは増えない |

シナリオの説明は [`packages/scenarios/src/index.ts`](packages/scenarios/src/index.ts)、現在のE2E操作とアサーションは [`packages/e2e-tests/tests/taskflow.e2e.ts`](packages/e2e-tests/tests/taskflow.e2e.ts) にあります。後者の操作文と前者の説明文が別々に管理されている点は、このPoCで残っている改善課題です。

## マニュアルサイトはどう更新されるか

一括処理は次の段階に分かれています。

1. E2EランナーがTaskFlowを開き、エージェントにシナリオを実行させる。
2. E2Eコードが期待した状態を確認し、JSONレポート、スクリーンショットなどを出力する。
3. `packages/docgen/`がレポートと証跡を検証し、シナリオ定義を使ってマニュアル・品質ページの候補を生成する。
4. Blumeがサイトをビルドし、リンクを検証する。
5. すべて成功した場合に限り、生成対象のローカルページと画像を更新する。

失敗・skip・必須アサーション不足・画像欠落・不正な証跡パスは成功として確定しません。失敗時は診断材料を残し、前回の正常なドキュメントを守る設計です。これは**検証済みの操作だけを公開候補にする仕組み**であり、手順をAIに自由生成させる仕組みではありません。

現時点では実E2Eの成功runがないため、成功した実データから生成されたマニュアルはありません。サイトに未検証の案内が出ているのは意図的です。

## 開発環境を準備する

Node.jsとpnpmのバージョンは[`.mise.toml`](.mise.toml)で固定しています。miseが利用できる場合:

```sh
mise install
pnpm install
```

miseを使わない場合は、`.mise.toml`に記載されたNode.js 24.22.3とpnpm 12.6.0を用意してください。

### アプリを起動する

それぞれ別のターミナルで起動します。

```sh
# ターミナル1: TaskFlow
pnpm dev:web
```

```sh
# ターミナル2: Blumeドキュメントサイト
pnpm dev:docs
```

- TaskFlow: <http://127.0.0.1:5173/>
- ドキュメント: <http://localhost:4321/>

TaskFlowはReact・TypeScript製で、タスクをブラウザーの`localStorage`に保存します。画面にはAstryxのCoreコンポーネントとNeutralテーマを使っています。UIを変更するときは [`apps/web/AGENTS.md`](apps/web/AGENTS.md) を確認してください。

## 検証コマンド

```sh
pnpm check       # フォーマット、Lint、型チェック
pnpm test:unit   # TaskFlowとdocgenの単体・契約テスト
```

ビルドとドキュメントのリンク検証:

```sh
pnpm --filter @living/web build
pnpm --filter @living/docs exec blume build --isolated
pnpm docs:validate
```

`--isolated`はBlume開発サーバーを起動したまま検証するためのビルドです。通常の`.blume/`ランタイムや`dist/`には触れず、`.blume-verify/`配下に出力します。通常のワークスペース全体ビルド`pnpm build`を行う場合は、Blume開発サーバーを止めてください。

2026-11-16時点では、`pnpm check`、TaskFlowの6件とdocgenの7件の単体・契約テスト、Web build、Blume isolated build・リンク検証が成功しています。Web buildにはバンドルサイズの警告があり、Astryx doctorでは外部フォントの読み込みを検証できない警告が出ます。**これらの結果は、実E2E成功や`docs:sync`完走を意味しません。**

## 実E2Eとドキュメント同期を実行する

このE2EはOpenAIのサインインを使います。APIキーを`.env.local`に書く方式ではありません。認証が必要な場合は、実行する人が自分のブラウザーでサインインしてください。

初回のみ、必要ならサンプル設定を用意します。既存ファイルは上書きしません。

```sh
test -f .env.local || cp .env.example .env.local
pnpm --filter @living/e2e-tests exec e2e login openai
```

6シナリオだけを実行する場合:

```sh
pnpm test:e2e
```

E2Eからマニュアル生成・サイト検証まで一括実行する場合:

```sh
pnpm docs:sync
```

`pnpm docs:sync`自体がE2Eを実行します。事前に成功runが必要なコマンドではありませんが、サインインが利用できないと完走できません。認証情報やログインコードはチャットに貼らず、`.env.local`もコミットしないでください。

## 出力と安全性

- E2Eランナーの結果は`packages/e2e-tests/.e2e/`に出力されます。
- `docs:sync`は実行ごとの診断用コピーを`.artifacts/e2e/<runId>/`に保存します。
- 生成候補は`.generated/`に作り、検証が通った後で`apps/docs/docs/manuals/`、`apps/docs/docs/quality/`、`apps/docs/public/evidence/`へ反映します。
- `.env.local`、E2E結果、生成途中の候補、ビルド成果物はGitの対象外です。秘密情報や個人情報を証跡に含めないでください。
- GitHub Actions、push起点の自動生成、外部ホスティングへのデプロイは設定していません。

## リポジトリの見取り図

```text
apps/
  web/                 # エージェントが操作するTaskFlow
  docs/                # Blumeサイトと生成対象のMDX
packages/
  scenarios/           # シナリオ・期待結果・手順の定義
  e2e-tests/           # エージェント操作、画面アサーション、証跡取得
  docgen/              # レポート/画像の検証とMDX生成
scripts/
  docs-sync.mjs        # E2EからBlume検証までのローカル一括処理
prd/                   # 要件、設計、制約、フェーズ別の受け入れ条件
```

背景と詳細仕様は [`prd/README.md`](prd/README.md) から読み進めてください。特に、目的は [`prd/00-product.md`](prd/00-product.md)、実装状況は [`prd/01-roadmap.md`](prd/01-roadmap.md)、失敗時の扱いは [`prd/architecture/contracts.md`](prd/architecture/contracts.md) にあります。

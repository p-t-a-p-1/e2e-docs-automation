# E2Eテスト・証跡 — 機能仕様

**関連:** PH-03 / **要件:** FR-01, FR-02

## 方針
`e2e`の `agent.act(...)` と確定的な `expect(...)` を組み合わせる。**AIの操作完了だけで成功にしない。** `app.screenshot(label)` で必要なチェックポイントの証跡を残す。テスト対象はVite+上のTaskFlow SPA。

## 対象シナリオ
| ID | シナリオ | 検証 |
|---|---|---|
| TC-001 | タスク追加 | 「牛乳を買う」が一覧に表示 |
| TC-002 | タスク編集 | 変更後のタイトルが表示 |
| TC-003 | 完了切替 | 完了状態が更新 |
| TC-004 | 削除 | 指定タスクが消える |
| TC-005 | 再読み込み | 保存されたデータを復元 |
| TC-006 | 空文字 | 不正なタスクが追加されない |

## 構成
- `packages/e2e-tests/` にe2eの設定とテストを集約。`packages/scenarios`を内部依存（`workspace:*`）として参照。
- `e2e.config.ts`からTaskFlowの `http://127.0.0.1:5173` に接続し、`pnpm --filter @living/web dev` で必要時に起動する。
- テスト名には `[TC-001]` 等の安定IDを含める。
- 初期状態は `app.clearState()` など、採用版で確認した方法を用いて独立化。
- JSON/HTMLレポート、画像、トレースを保存し、ローカル診断領域にコピーする。

## 必須条件
- 6シナリオで明示的アサーションと撮影ポイントを実装。
- スキップを成功とみなさない。モデル未設定なら明確に失敗/ブロック扱い。
- 採用したe2eのCLI/config/reporter/出力APIを初期スパイクで確認して固定する。
- テスト失敗時は非ゼロ終了する。

# リスク・対策（ローカルMVP）

| ID | リスク | 対策・判定 |
|---|---|---|
| R-01 | e2eのAPI/レポート変更 | バージョン固定、Adapter隔離、fixture、未知形式拒否 |
| R-02 | AI操作の非決定性 | 明示的assertion、テストデータ初期化、固定viewport、リトライ制御 |
| R-03 | 未検証手順の混入 | シナリオ正本から決定的MDX生成、任意AI改善の構造照合 |
| R-04 | 異常runで正常版を上書き | 候補生成→検証→確定、失敗時ロールバック、非ゼロ終了 |
| R-05 | 画像・ログへの秘密情報流入 | サンプル固定データ、マスキング、出力前検査 |
| R-06 | 画像パス不整合 | 実在/メディア型/パス検証、Blumeリンクチェック |
| R-07 | モデル認証・コスト | ローカル `.env`、シークレット非コミット、キャッシュ、失敗時明示 |
| R-08 | Vite+とTurborepoでタスク重複 | TurboのみがmonorepoのDAGを管理し、Vite+はpackage内の処理に限定 |
| R-09 | BlumeとVite+で設定衝突 | Blumeは専用CLI、Vite+はSPA側に限定。Nodeバージョン固定 |
| R-10 | ローカル二重実行で生成物破損 | 実行別の一時領域・排他制御・原子的更新/復元 |
| R-11 | CIなしで毎回実行忘れ | `pnpm docs:sync`のREADME明記、将来CI導入検討（今回対象外） |

## 初回の実機確認項目
- Node / pnpm / turbo / vite-plus / e2e / Blumeの互換性と固定バージョン。
- `vp check`の対象とBlume MDXの扱い。
- e2eのレポート位置、AI認証、Vite+サーバー起動、画像保存。
- `pnpm docs:sync`が途中失敗しても最後の正常版が残るか。
